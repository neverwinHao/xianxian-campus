# 从照片参照到 JavaScript 模型

本项目的几何直接在浏览器里生成。照片用于判断平面关系和立面特征，再由人工把判断写成参数与构建函数；没有自动摄影测量、AI 图片转网格或 Blender 导出步骤。

```mermaid
flowchart LR
  A[航拍、近照和位置指认] --> B[校区坐标与楼体参数]
  B --> C[几何构件与建筑样式]
  C --> D[Three.js 场景]
  D --> E[浏览、漫游和徒步]
```

## 1. 建立校园坐标

`src/campuses.js` 是模型的参数表。使用局部场景坐标：`+X` 向东、`-Z` 向北，`Y` 是高度；场景单位是近似尺度，不是经过地理配准的测量数据。

每个校区包括外边界 `boundary`、入口 `gate`、建筑 `buildings`、道路 `roads`、绿地 `gardens` 和其他景观。先确认校门朝向与楼群前后关系，再逐栋调整中心坐标、宽、深和高。

当前北校区从南侧进入，南校区从北侧进入。照片中的“左右”要先换算到入校方向，不能直接当成东西方向。

## 2. 用参数描述一栋楼

下面是北校区 A 部宿舍的关键字段，完整配置在 `campuses.js`：

```js
{
  id: 'middle-west',
  name: 'A部宿舍',
  x: -76,
  z: -12,
  w: 106,
  d: 25,
  h: 21,
  kind: 'building',
  profile: 'northPlain',
  roofPanels: false,
  closeFace: 'south',
  labelPriority: 1
}
```

| 字段                | 控制的内容                       |
| ------------------- | -------------------------------- |
| `id`                | 稳定标识，供点选、搜索、漫游引用 |
| `x`、`z`            | 建筑在校园里的中心位置           |
| `w`、`d`、`h`       | 宽度、进深和高度                 |
| `profile`           | 立面与构件的生成规则             |
| `roofPanels`        | 屋顶深色板阵列是否生成           |
| `courtyard`、`wing` | 是否围合院落，以及翼楼宽度       |
| `closeFace`         | 近景从哪一面观察                 |
| `labelPriority`     | 标注避让时的优先级               |

这些 `id` 最初按方位命名，因此 `middle-west` 现在表示 A 部宿舍。改用途时保留稳定 ID，可以减少交互引用的连锁修改。

## 3. 先做体量，再补细节

`src/scene.js` 的 `buildBuilding()` 根据 `profile` 选择构建函数。重复形状由基础构件拼装，特殊形状通过顶点和索引生成。

| 构件       | 代码入口                       | 做法                                       |
| ---------- | ------------------------------ | ------------------------------------------ |
| 常规楼体   | `buildingBlock()`              | 长方体外墙、分层窗组、端部构件             |
| 北校区楼体 | `northPhotoBlock()`            | 红白立面、窗带、立柱与坡顶                 |
| 北校区食堂 | `northCanteen()`               | 两层大窗、橘红墙面、灰白柱、中央门厅和台阶 |
| 四坡屋顶   | `hipGeometry()`、`northRoof()` | 自定义屋顶顶点，添加脊线、接缝和深色板     |
| 南校区楼体 | `southPhotoBlock()`            | 根据科技楼、食堂、宿舍等样式调整窗距和立面 |
| 教学楼院落 | `southTeachingCourt()`         | 四周翼楼、中央分隔楼、两处银杏天井         |
| 宿舍院落   | `southDormCourt()`             | 单院落，避免复制教学楼的双天井结构         |
| 图书馆     | `southLibrary()`               | 独立楼体、绿色玻璃、屋顶题字               |

建模时先校对体量与楼距，确认之后再加屋顶、窗户、门厅和附属构件。这样修正整体布局时，不必重写每个窗户的位置。

## 4. 景观、校门与雕塑

- `localBuilder()` 把构件局部坐标转换到世界坐标，用于有朝向的校门、亭子与景观。
- `gate()` 分别构造两校区入口，包含门柱、门卫室、雨棚、伸缩门和程序生成的校名。
- `northLandscape()` 生成北校区庭院、曲廊、树池和车辆；门前曲廊在入门左侧。
- `northSculpture()` 用曲线采样、横向宽度和厚度构造银色带状网格，再添加支撑管、基座与分瓣花坛；雕塑在入门右侧。
- `tree()` 使用树干和低面数树冠。`ginkgoTree()` 使用枝干与扇形叶片；树木不是图片平面。
- `track()` 生成跑道和球场线，北校区不生成体育场。

题字和胸徽使用 Canvas 画文字，再转成小尺寸纹理。材质色彩和校服渐变也由代码定义，没有使用实景照片裁片。

## 5. 控制绘制成本

`mat()` 缓存材质，`add()` 按“几何 + 材质”收集变换矩阵，`finishBatches()` 创建 `InstancedMesh`。窗户、树叶、栏杆等重复构件可以共享一次实例绘制。

校区加载使用固定随机种子，树冠变化可复现。切换校区时，`disposeRoot()` 释放旧几何、材质和纹理；角色也会解除自己的输入监听。

## 6. 模型与显示名单分开

`displayIds` 决定列表和地图标签显示什么；`tour` 决定漫游顺序；`selectionAliases` 可把同组附属构件映射到一个主地点。

北校区 A/B 部宿舍是与前排教学楼通过连廊连接的中排两栋。食堂后面的楼体保留模型，但不进入显示名单和漫游。南校区后方宿舍、食堂和图书馆同样保留模型，页面只显示用户指定的四个地点。

因此，“不标注”应该调整 `displayIds` 和 `tour`，不应该删除 `buildings` 中的几何配置。

## 7. 校服小人与步行

`src/walk.js` 分为三部分：

1. `avatar()`：躯干、头发、眼镜、手臂、腿、鞋和胸徽；蓝白外套通过顶点颜色渐变生成。
2. `navigation()`：将建筑转换为障碍矩形，检查校园边界，寻找安全出生点，计算滑墙移动和镜头遮挡。
3. `create()`：接入键盘和摇杆，把输入转换为相机方向上的速度，更新关节摆动与跟随相机。

摆腿和摆臂相位由实际移动距离推进，因此撞墙停下时不会继续原地走路。长帧时间被限制，位移分成小步检查，减少穿墙。

这是室外平面步行。建筑内部、逐层楼梯和所有树木的精细碰撞没有建立。

## 8. 一次常见修改

例如调整 A 部宿舍位置：

1. 修改 `campuses.js` 中 `middle-west` 的 `x`、`z` 或尺寸。
2. 同时检查 `connectors` 与教学楼是否仍然相接，避免路面和楼体重叠。
3. 核对 `displayIds`、`tour` 与名称，不把宿舍重新映射为教学楼。
4. 执行 `npm run check`、`npm test`、`npm run build`。
5. 在浏览器查看鸟瞰、近景和徒步经过楼边的结果。

测试可以验证碰撞和引用关系，真实建筑的用途与位置仍需用可靠资料核对。
